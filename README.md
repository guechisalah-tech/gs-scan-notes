# GS Scan Notes — استخراج نقاط التلاميذ من الصور وإدراجها في Excel

تطبيق Android (Flutter) يساعد الأستاذ على إدخال النقاط: يستورد قائمة التلاميذ من ملف Excel، ثم يقرأ كشف النقاط من صورة (OCR محلي بدون إنترنت)، ويطابق الأسماء، ويعرض النتائج للمراجعة، ثم يحفظ **نسخة جديدة** من الملف.

> ⚠️ **حالة الإصدار 1.0:** كُتب الكود كاملًا لكن لم يُترجم (compile) ولم يُجرَّب على هاتف حقيقي في بيئة الإنشاء (لا يتوفر Flutter فيها). أول بناء على GitHub هو أول اختبار فعلي. إن فشل أي خطوة في Actions ابعث لي نص الخطأ لأصلحه. (انظر "حدود الإصدار الأول".)

## 1) رفع المشروع إلى GitHub وبناء APK

1. أنشئ مستودعًا جديدًا على GitHub (مثلًا `gs-scan-notes`).
2. فك ضغط الحزمة وارفع **محتويات المجلد** `gs_scan_notes` إلى المستودع (المجلد `.github` مخفي، تأكد أنه رُفع).
   - من الويب: *Add file → Upload files* ثم اسحب الملفات والمجلدات.
   - أو بالأوامر:
     ```bash
     cd gs_scan_notes
     git init && git add . && git commit -m "GS Scan Notes v1"
     git branch -M main
     git remote add origin https://github.com/<حسابك>/gs-scan-notes.git
     git push -u origin main
     ```
3. افتح تبويب **Actions** ← اختر **Build APK** ← **Run workflow**.
   (يعمل أيضًا تلقائيًا عند كل push على `main`.)
4. انتظر 8–15 دقيقة تقريبًا. عند النجاح افتح التشغيل ← قسم **Artifacts** ← حمّل **GS-Scan-Notes-APK** (ملف zip فيه `app-release.apk`).
5. انقل `app-release.apk` إلى الهاتف وثبّته (فعّل "التثبيت من مصادر غير معروفة").

ما يفعله الـ Workflow: يثبت Java 17 وFlutter (stable)، ثم يولّد هيكل Android بـ `flutter create`، ويضع `android_overrides/AndroidManifest.xml`، ويرفع `minSdk` إلى 24، ثم `pub get` وتحليل واختبارات (غير مانعة) و`flutter build apk --release`.

### بناء محلي (اختياري)
```bash
flutter create --platforms=android --org com.gsscan --project-name gs_scan_notes .
cp android_overrides/AndroidManifest.xml android/app/src/main/AndroidManifest.xml
# ثم اجعل minSdk = 24 في android/app/build.gradle(.kts)
flutter pub get && flutter test && flutter build apk --release
```

## 2) طريقة الاستخدام

1. **استيراد ملف Excel** (.xlsx). يقترح التطبيق تلقائيًا سطر العناوين وأعمدة (اللقب/الاسم/الرقم/النقاط)؛ راجعها في شاشة **إعداد الأعمدة**، واختر الورقة (Sheet). إن اخترت "عمود جديد" فسيُنشأ عمود `Note`.
2. **تصوير** كشف النقاط أو **اختيار صورة**. تفتح شاشة القص والتدوير: **اقصص الجدول فقط، وعمود نقطة واحد** في الصورة.
3. اضبط **موضع عمود النقطة** (أقصى اليمين للجداول اللاتينية، أو اليسار) والحد الأقصى (20 مثلًا).
4. **استخراج النقاط** ← تنتقل تلقائيًا لشاشة **المراجعة**.
5. في المراجعة (جدول: اللقب | الاسم | النقطة | التلميذ المطابق | الحالة):
   - **مؤكدة** (خضراء): مطابقة برقم التلميذ أو باسم مطابق تمامًا وفريد. مُعتمدة افتراضيًا.
   - **غير مؤكدة** (برتقالية): تشابه تقريبي، اسم مكرر، أو رقم لا يوافق الاسم. **لا تُدرج حتى تضغط عليها وتعتمدها**.
   - **مفقودة** (حمراء): غير موجودة في القائمة؛ اختر التلميذ يدويًا إن أردت.
   - اضغط أي صف لتعديل اللقب/الاسم/النقطة، أو اختيار التلميذ، أو إعادة المطابقة، أو التجاهل.
   - قائمة ⋮: اعتماد كل المؤكدة، إعادة المطابقة، **الأسطر المتجاوزة** (أسطر بها أسماء بلا نقطة مقروءة)، إضافة صف يدويًا.
6. **حفظ ملف Excel**: ملخص ← تأكيد ← اختيار مكان الحفظ. الاسم: `Notes_Importees_2026.xlsx`. الملف الأصلي لا يتغير.

### ضمانات الأمان في المطابقة والحفظ
- لا يُدرج أي صف غير معتمد. المطابقة التقريبية لا تُعتبر مؤكدة أبدًا.
- إن استهدف صفّان نفس التلميذ يُمنع الحفظ حتى تتجاهل أحدهما.
- نقطة خارج [0 – الحد الأقصى] لا يمكن اعتمادها.
- إن وُجدت قيمة في خلية النقاط تُعرض عبارة "تستبدل: x" ويُذكر عددها قبل الحفظ.
- التعديل يتم داخل XML الملف مباشرة: باقي الأعمدة والأوراق والتنسيق والدمج والعرض تبقى كما هي.

## 3-ب) الجداول العربية (رقم التعريف) — الإصدار 1.1

كشوف النقاط المدرسية الجزائرية غالبًا بأسماء **عربية** وأرقام تعريف من 16 رقمًا. محرك OCR المحلي لا يقرأ العربية، لذلك:

- **المطابقة برقم التعريف فقط**: تُفعَّل تلقائيًا إن كانت أسماء ملفك عربية (ويمكنك تبديلها من "خيارات الاستخراج"). حدد عمود **رقم التعريف** في "إعداد الأعمدة". رقم قريب بخطأ رقم أو رقمين يُعرض "غير مؤكد" ولا يُعتمد تلقائيًا.
- **عدة أعمدة نقاط** (نشاطات، فرض، اختبار): بعد الاستخراج تظهر نافذة تعرض الأعمدة الرقمية المكتشفة مع عيّنة قيم، فتختار العمود المطلوب. في "إعداد الأعمدة" اختر عمود Excel المقابل (مثلًا "الفرض").
- **النص المقروء**: من ⋮ في شاشة المراجعة تجد "النص المقروء من الصورة" لمعرفة ما قرأه المحرك فعلًا.
- **الإدخال اليدوي** (بدون صورة): من الشاشة الرئيسية، قائمة تلاميذ ملفك وحقل نقطة أمام كل اسم، ثم المراجعة والحفظ. هو البديل المضمون إن فشلت قراءة الصورة.
- الخط اليدوي أصعب على OCR من الطباعة: تُقرأ بعض الأرقام خطأ أو لا تُقرأ، فراجع النتائج دائمًا. صوّر الجدول قريبًا وبإضاءة متساوية، ويفضّل تصوير نصف الصفحة في كل مرة.

## 4) حدود الإصدار الأول (بصراحة)

- **اللغة:** محرك OCR المحلي (Google ML Kit، مضمّن بلا إنترنت) يقرأ **الحروف اللاتينية والأرقام** فقط. الأسماء المكتوبة بالحروف العربية في الصورة **غير مدعومة**. البديل العملي: اعتمد قوائم لاتينية (Nom/Prénom كما في Excel الجزائري عادة)، أو أضف/عدّل الصفوف يدويًا في المراجعة (والمطابقة بالرقم إن كان الرقم لاتينيًا). الأسماء العربية في ملف Excel نفسه مدعومة في المطابقة (للمقارنة اليدوية).
- **عمود نقاط واحد لكل صورة:** إن كان في الكشف عدة أعمدة نقاط (فرض، اختبار، معدل) فاقصص الصورة بحيث يبقى العمود المطلوب فقط.
- **الدقة:** الأفضل صورة مسطحة بإضاءة متساوية والجدول يملأ الصورة. الميل البسيط يُصحَّح تلقائيًا، والكبير ينبغي تدويره من شاشة القص. الخط اليدوي دقته ضعيفة؛ راجع كل النتائج.
- الأسطر بلا نقطة مقروءة لا تصير صفوفًا تلقائيًا؛ ستجدها في "الأسطر المتجاوزة".
- صيغة **.xls** القديمة غير مدعومة (احفظها .xlsx). الملفات المحمية بكلمة مرور غير مدعومة.
- الخلايا المستبدلة التي كانت تحتوي صيغة: يُحذف `calcChain` تلقائيًا ليفتح Excel الملف دون شكوى.
- **لم يُختبر على جهاز حقيقي** (انظر أعلى الصفحة). قد تظهر أخطاء توافق إصدارات مكتبات عند أول بناء.

## 5) الخصوصية

- لا يوجد إذن `INTERNET` في Manifest: التطبيق **لا يستطيع** إرسال أي شيء.
- الصور تُعالج في ذاكرة التخزين المؤقت للتطبيق وتُحذف نسخة المعالجة بعد الاستخراج، وتُحذف الصورة عند إزالتها أو "جلسة جديدة" (الصور في معرضك لا تُحذف أبدًا).
- الملف الأصلي لا يُعدَّل ولا يُحذف.
